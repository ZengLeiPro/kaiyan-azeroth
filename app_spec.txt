<project_specification>
  <project_name>Azeroth（KY-Azeroth）</project_name>

  <overview>
    企业级 CRM + 项目管理 + 工作汇报 + 审批流 内部管理系统。
    面向中小企业，提供客户关系管理、销售全流程、项目与工时管理、组织人事、审批工作流、钉钉数据同步等一站式解决方案。
    架构遵循"Single Source of Truth"（shared 包唯一事实来源）、"严格类型安全"（Zod + TypeScript）、"规范化 CRUD"（useCrud + CrudTable 四层架构）的理念。
    所有迭代开发必须完全遵循 rules.md 中定义的 MUST/SHOULD/MAY 规范。
  </overview>

  <prerequisites>
    <environment_setup>
      - Node.js >= 22, pnpm >= 9
      - Docker + Docker Compose（本地 PostgreSQL + Redis + MinIO）
      - 运行 pnpm install 安装依赖
      - 复制 .env.example 为 .env 并配置数据库连接

  <core_modules>
    <crm description="客户关系管理，9个子模块">
      - 客户管理（Customer）：客户信息、等级、来源、标签、区域地址
      - 联系人（Contact）：客户关联联系人，决策人标记
      - 商机（Opportunity）：销售漏斗，阶段、金额、赢率、预计成交
      - 合同订单（SaleOrder）：订单管理，产品明细行（快照模式）
      - 回款管理（Payment）：回款记录，关联订单与客户
      - 开票管理（Invoice）：发票记录，类型、税号、状态
      - 跟进记录（KeepRecord）：客户跟进，类型、签到、附件
      - 拜访签到（VisitRecord）：上门拜访，签到签退、时长、地址
      - 产品管理（CrmProduct）：产品目录，独立于订单快照
    </crm>

    <project_management description="项目管理，3个子模块">
      - 项目列表（Project）：项目信息、成员管理
      - 工作项（WorkItem）：任务/缺陷/需求，分配、优先级、进度
      - 工时记录（EffortRecord）：工作日志，实际工时、工作类型
    </project_management>

    <reports description="工作汇报，4个子模块（只读）">
      - CRM日报（CrmWorkDaily）：销售日报，今日拜访/跟进汇总
      - 钉钉日志（DingtalkLog）：从钉钉同步的日志数据
      - 日程事件（DingtalkCalendarEvent）：从钉钉同步的日历事件
      - 离职记录（EmployeeLeave）：离职人员记录
    </reports>

    <organization description="组织架构，2个子模块">
      - 员工管理（Employee）：员工信息、钉钉关联、入职/在职/离职
      - 部门管理（Department）：部门树形结构、部门经理、员工归属
    </organization>

    <approval description="审批管理，完整审批工作流">
      - 审批流程设计（ApprovalFlow）：可视化流程设计器，多节点审批
      - 审批列表（ApprovalInstance）：待办、已办、我发起的、抄送我的
      - 审批操作：提交、审批、驳回、撤回、管理员强制审批
    </approval>

    <system description="系统管理，6个子模块">
      - 用户管理（User）：账号、角色分配、密码管理
      - 角色权限（Role）：RBAC，模块级细粒度权限
      - 系统参数（SystemConfig）：全局配置项
      - 操作日志（OperationLog）：操作审计追溯
      - 登录日志（LoginLog）：登录行为审计
      - 通知中心（Notification）：站内通知
    </system>

    <other description="辅助功能">
      - 仪表盘（Dashboard）：数据统计总览
      - 回收站（Trash）：软删除数据恢复
      - 深色/浅色主题切换
      - 命令面板（Command Palette）：全局快速搜索
      - UI 演示页面：组件展示
    </other>
  </core_modules>

  <database_schema>
    <summary>
      32 个 Prisma Model，分为 6 大类：
      - 系统核心（10）：User, Session, Role, UserRole, RolePermission, SystemConfig, OperationLog, LoginLog, Notification, SerialNumberCounter
      - 组织架构（3）：Employee, Department, EmployeeDepartment
      - CRM（14）：Customer, Contact, Opportunity, SaleOrder, Payment, Invoice, KeepRecord, VisitRecord, CrmProduct, OpportunityProduct, OrderProduct, CrmWorkDaily
      - 项目管理（4）：Project, ProjectMember, WorkItem, EffortRecord
      - 审批系统（5）：ApprovalFlow, ApprovalFlowNode, ApprovalInstance, ApprovalTask, ApprovalRecord
      - 钉钉同步（3+1）：DingtalkLog, DingtalkCalendarEvent, EmployeeLeave, SyncState
    </summary>
    <conventions>
      - 所有模型包含 6 个审计字段：createdAt, updatedAt, deletedAt, createdBy, updatedBy, version
      - 业务实体使用软删除（deletedAt），不设 onDelete: Cascade
      - 枚举使用 String + 常量，不使用 Prisma enum
      - 所有外键字段必须添加 @@index
      - Decimal 精度敏感字段使用 @precision 注释
    </conventions>
  </database_schema>

  <governance_rules>
    所有开发必须遵循 rules.md 中的 MUST 规范（强制），包括：
    - Single Source of Truth：shared 包唯一事实来源
    - 前端类型强绑定：Profile extends IXxxResponse
    - Zod 表单验证：useCrud 必须传入 schema
    - 后端 DTO：必须使用 nestjs-zod（createZodDto）
    - Decimal 精度：读取 Number()，提交 String()
    - 类型安全：禁止 any / @ts-ignore
    - Prisma 规范：禁止 db push / 手写 SQL / 跳过迁移
    - API 路由：扁平风格，Controller 不写版本号
    - 安全规范：JWT Guard / Helmet / CORS / XSS 防护
    - 25 项自动化检查脚本（pnpm run check:all）
    提交前必须通过 pnpm run check:all + pnpm typecheck + pnpm build
  </governance_rules>
